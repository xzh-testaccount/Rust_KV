# 需求规格与验收

## 1. 项目目标

使用 Rust 实现一个支持数据保存和多客户端访问的键值存储系统，由服务器程序和命令行客户端组成。服务器负责共享内存数据、持久化和请求处理；客户端负责用户交互和显示结果。

## 2. 阶段目标与验收矩阵

| 阶段 | 必须完成的行为 | 验收方式 | 通过标准 |
| --- | --- | --- | --- |
| 一、项目框架 | 工程可编译；协议、存储、持久化、网络、客户端职责分离 | `cargo build`；检查模块边界 | 构建成功，入口不集中承载全部功能 |
| 二、命令与通信 | 合法命令、未知命令、缺参、多参、非法文本均有确定结果；请求和响应一问一答 | 离线解析单元测试；协议测试 | 每项输入得到规定响应/错误码，错误后可继续 |
| 三、内存存储 | 新增、覆盖、查询、删除、排序列键、数量统计 | 存储单元测试 | 所有结果与命令语义一致 |
| 四、持久化恢复 | 每次成功修改先可靠写入 WAL；重启恢复最终状态；损坏文件不被忽略 | 临时数据文件重启测试；损坏样例测试 | set、覆盖、delete 均可恢复；坏文件启动失败 |
| 五、单客户端 | TCP 连续处理请求；支持分段、粘包、超长和非法输入 | 客户端—服务器集成测试 | 同一连接可连续完成写入、查询、状态、删除、退出 |
| 六、多客户端 | 每连接独立线程；共享数据和 WAL 安全；连接错误隔离 | 多线程/多客户端测试 | 无数据竞争、无 WAL 交错损坏，已确认数据可恢复 |
| 七、集成验收 | 启动方式、文档、自动测试和提交内容完整 | 全部命令和演示最终执行 | 格式、Clippy、测试、演示均满足要求 |

## 3. 功能需求

服务器必须实现以下固定命令：

| 命令 | 参数 | 语义 | 失败情况 |
| --- | --- | --- | --- |
| `set` | `key value` | 新增或覆盖；返回是否覆盖 | 缺参、多参、非法键/值、持久化失败 |
| `get` | `key` | 返回键对应值 | 缺参、多参、非法键、键不存在 |
| `delete` | `key` | 删除键 | 缺参、多参、非法键、键不存在、持久化失败 |
| `keys` | 无 | 返回全部键，按字典序排列 | 多余参数、响应帧超限 |
| `status` | 无 | 返回当前键数量 | 多余参数 |
| `ping` | 无 | 返回 `pong` | 多余参数 |
| `quit` | 无 | 返回成功响应后关闭当前连接 | 多余参数 |

键使用 UTF-8 字节长度不超过 256；值使用 UTF-8 字节长度不超过 16 KiB。键不得为空或包含空白字符、控制字符；值不得为空且不得包含控制字符。具体 JSON 字段和错误码以[协议与持久化设计](协议与持久化设计.md)为唯一依据。

## 4. 非功能需求

- 默认 TCP 地址为 `127.0.0.1:7878`，默认数据文件为 `data/kv.wal`。
- 单帧最大 64 KiB，不含末尾 LF；超限帧不得导致进程崩溃。
- 网络读取、协议解析和响应发送期间不得持有存储锁。
- 单个客户端的非法请求或异常断开不得终止服务器。
- 持久化写入未完成时，内存不得更新且不得向客户端报告成功。
- 文件截断、非法记录或格式损坏必须显式报告并拒绝启动。
- 代码和文档必须说明 Windows 已实测、Linux 尚未实测；不能把未执行的网络/并发测试写成已通过。

## 5. 提交验收

Windows 发布版已于 2026-08-31 完成真实验收；以下命令可复核构建与自动化结果，Linux 仍需在目标环境执行：

```text
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
cargo build
```

Windows 发布版已完成并通过[测试、环境与演示](测试环境与演示.md)中的双客户端和重启恢复演示；提交时仍须确认目录不含编译产物、运行时 WAL 和临时文件。Linux 尚未实测。
