# 协议与持久化设计

## 1. 传输和帧边界

- 传输协议为 TCP，默认地址 `127.0.0.1:7878`。
- 消息采用 UTF-8 JSON Lines；每个请求和响应占一行。
- 每帧逻辑内容最大 65,536 字节（64 KiB），不计算结尾 LF。
- 请求必须以 LF 结束；CRLF 中的 `\r` 会被去除后再解析。
- 非 UTF-8、非法 JSON、超长帧都返回错误；超长帧应丢弃到下一个 LF，然后继续处理下一帧。
- EOF 前的非空未结束内容是协议错误，连接关闭。
- 响应也必须是单个完整 JSON 帧；不能发送半个响应。生成的响应超过 64 KiB 时返回 `FRAME_TOO_LARGE`，不得截断。

## 2. 请求格式和命令语义

请求必须是 JSON 对象，字段名和字段类型固定。未知字段视为多余参数。

```json
{"cmd":"set","key":"name","value":"Alice"}
{"cmd":"get","key":"name"}
{"cmd":"delete","key":"name"}
{"cmd":"keys"}
{"cmd":"status"}
{"cmd":"storage_status"}
{"cmd":"compact"}
{"cmd":"ping"}
{"cmd":"quit"}
```

固定语义：

- `set` 新增或覆盖，成功响应含 `replaced: false/true`。
- `get` 返回值；键不存在返回 `NOT_FOUND`。
- `delete` 删除键；键不存在返回 `NOT_FOUND`。
- `keys` 返回全部键的字典序列表和数量。
- `status` 返回当前键数量。
- `storage_status` 返回内存条目数、WAL 记录数和字节数、Snapshot 字节数、最后序号及可写状态。
- `compact` 生成当前状态 Snapshot 并截断已被覆盖的 WAL，返回压缩前后统计和耗时。
- `ping` 返回成功响应，用于健康探测。
- `quit` 返回成功响应后关闭当前连接。

键不得为空、不得含空白字符或控制字符，UTF-8 字节数不超过 256；值不得为空、不得含控制字符，UTF-8 字节数不超过 16 KiB。

## 3. 响应和错误码

成功响应使用 `ok: true`，例如：

```json
{"ok":true,"data":{"kind":"set","replaced":false}}
{"ok":true,"data":{"kind":"get","value":"Alice"}}
{"ok":true,"data":{"kind":"delete","deleted":true}}
{"ok":true,"data":{"kind":"keys","keys":["a","b"],"count":2}}
{"ok":true,"data":{"kind":"status","count":2}}
{"ok":true,"data":{"kind":"storage_status","entries":2,"wal_records":3,"wal_bytes":321,"snapshot_bytes":0,"last_sequence":3,"writable":true}}
{"ok":true,"data":{"kind":"compact","entries":2,"compact_ms":4,"wal_records_before":3,"wal_bytes_before":321,"snapshot_bytes_before":0,"last_sequence_before":3,"wal_records_after":0,"wal_bytes_after":0,"snapshot_bytes_after":156,"last_sequence_after":3}}
{"ok":true,"data":{"kind":"ping"}}
{"ok":true,"data":{"kind":"quit"}}
```

失败响应固定为：

```json
{"ok":false,"error":{"code":"INVALID_JSON","message":"..."}}
```

错误码只能使用下列值：

| 错误码 | 含义 |
| --- | --- |
| `INVALID_UTF8` | 帧不是合法 UTF-8 |
| `INVALID_JSON` | JSON 语法错误 |
| `INVALID_REQUEST` | JSON 不是合法请求对象或请求内容为空 |
| `UNKNOWN_COMMAND` | `cmd` 不是规定命令 |
| `MISSING_ARGUMENT` | 缺少必需字段 |
| `EXTRA_ARGUMENT` | 有未知字段或多余参数 |
| `INVALID_KEY` | 键为空、含空白/控制字符或超长 |
| `INVALID_VALUE` | 值为空、含控制字符、类型错误或超长 |
| `NOT_FOUND` | 查询或删除的键不存在 |
| `FRAME_TOO_LARGE` | 请求或响应超过 64 KiB |
| `STORAGE_ERROR` | 运行时存储或持久化 IO 失败 |

单条请求错误不会关闭仍有完整帧边界的连接。连接 EOF 不发送伪造响应，只结束当前连接。

## 4. WAL 与 Snapshot 格式

WAL 是追加式 UTF-8 JSON Lines，每条记录必须以 LF 结束。单条记录的原始 JSON payload（不含结尾 LF）最大为 65,536 字节（64 KiB）；超过此上限的记录属于持久化损坏：

```json
{"payload":{"version":1,"seq":1,"record":{"op":"set","key":"name","value":"Alice"}},"crc32":"XXXXXXXX"}
{"payload":{"version":1,"seq":2,"record":{"op":"delete","key":"name"}},"crc32":"XXXXXXXX"}
```

`XXXXXXXX` 是根据 `payload` 标准 JSON 字节计算出的 8 位十六进制 CRC32。`seq` 是全局连续操作序号，用来检测记录缺失、重复或乱序；CRC32 用来检测内容变化。只允许 `set` 和 `delete` 两种操作，键和值沿用网络请求校验规则。

基础版 `{record, crc32}` WAL 可以在文件开头平滑读取，恢复时按出现顺序赋予逻辑序号；一旦出现新版记录，后面不允许再混入旧版记录。没有 CRC32 的历史格式不兼容。

Snapshot 路径由 WAL 路径替换扩展名得到，例如 `data/kv.wal` 对应 `data/kv.snapshot`。文件保存某一时刻的最终有序键值，而不是操作日志：

```json
{"payload":{"version":1,"last_seq":2,"entries":[{"key":"course","value":"Rust"} ]},"crc32":"YYYYYYYY"}
```

Snapshot 最大 64 MiB，键必须严格按字典序排列且不能重复。`YYYYYYYY` 校验整个 Snapshot payload；版本、CRC32、键值规则或结构不合法时拒绝恢复。

## 5. 写入、恢复与压缩

一次 `set` 或 `delete` 必须在共享锁内按下列顺序执行：

1. 分配下一个连续 `seq`，构造操作内容并计算 CRC32，生成完整 WAL 记录。
2. 追加记录。
3. `flush`。
4. `sync_data`。
5. 更新内存 `BTreeMap`。
6. 释放锁并返回成功响应。

追加、刷新或同步失败时，不更新内存、不返回成功，并报告 `STORAGE_ERROR`。

启动恢复按以下顺序执行：

1. 若正式 Snapshot 缺失但 `.bak` 存在，先恢复备份；未发布的 `.tmp` 不参与恢复。
2. 校验并加载 Snapshot，得到最终键值和 `last_seq`；没有 Snapshot 时从空 Store、序号 0 开始。
3. 逐行校验 WAL 的版本、CRC32 与连续序号，只重放 `seq > last_seq` 的增量记录。
4. 任一持久化文件损坏时拒绝启动并报告原因，不跳过、不自动覆盖问题文件。

`compact()` 在写锁内执行：同步并关闭 WAL 写入器 → 写 `kv.snapshot.tmp` → `flush + sync_data` → 回读校验 → 将旧正式快照保留为 `.bak` 并发布新快照 → 截断和同步 WAL → 重新打开追加写入器。发布 Snapshot 早于截断 WAL，因此即使两个步骤之间崩溃，重复记录也会因 `last_seq` 被安全跳过，不会丢失已确认数据。
