## 4. 测试案例

| 编号 | 场景 | 操作 | 预期 |
| --- | --- | --- | --- |
| T-01 | 基本写读 | set 后 get | 返回写入值和 `ok:true` |
| T-02 | 覆盖 | 对同一键 set 两次 | 第二次返回 `replaced:true`，get 为新值 |
| T-03 | 删除 | delete 后 get/delete | 首次删除成功，再次返回 `NOT_FOUND` |
| T-04 | 列表统计 | 写入多个键后 keys/status | keys 字典序正确，count 准确 |
| T-05 | 解析错误 | 未知命令、缺参、多余字段、非法键值 | 分别返回固定错误码，下一条合法请求仍成功 |
| T-06 | 持久化恢复 | set、覆盖、delete，停止并用同一组 Snapshot/WAL 重启 | 只恢复最后状态 |
| T-07 | 持久化损坏 | 截断 WAL、坏 JSON、CRC32 错误、序号缺口或坏 Snapshot | 启动失败，问题文件不被覆盖 |
| T-08 | 帧边界 | 分段发送、多条请求合并发送、CRLF | 每帧独立处理，响应一问一答 |
| T-09 | 超长/非法文本 | 超过 64 KiB、非 UTF-8 | 返回 `FRAME_TOO_LARGE`/`INVALID_UTF8`，可继续时继续 |
| T-10 | 单客户端 | set/get/status/delete/quit 连续执行 | 同连接全部按顺序完成 |
| T-11 | 双客户端 | 两个客户端同时写入和查询不同键 | 两连接互不阻塞崩溃，结果可读 |
| T-12 | 并发恢复 | 多客户端完成修改后重启 | 所有已确认修改可恢复，WAL 无交错损坏 |
| T-13 | Snapshot 压缩 | 写入覆盖历史 → compact → 重启 → 再写入并重启 | WAL 收敛，状态不变，序号连续，增量操作可恢复 |
| T-14 | 基础/创新对比 | 两个实现使用相同 2,000 次写入和 100 个最终键 | 输出文件大小、恢复耗时、压缩暂停和写入时间；数据可复现 |

并发测试不应断言未排序线程的“最终胜者”；应验证每个成功写入都按锁定顺序进入 WAL，且重启后状态与该顺序一致。

## 5. 双客户端和重启恢复演示

以下是已通过的 Windows 发布版演示流程及其复现步骤。每个 `cargo run` 应在独立终端运行。

终端 A 启动服务器：

```powershell
cargo run --bin kv-server -- --bind 127.0.0.1:7878 --data data/kv.wal
```

终端 B 启动客户端并执行：

```text
set course rust
get course
status
```

终端 C 启动第二个客户端并执行：

```text
set client2 online
keys
ping
```

终端 B 再执行：

```text
keys
get client2
delete course
quit
```

终端 C 执行 `get course`，应得到 `NOT_FOUND`，然后执行 `quit`。停止服务器后，用完全相同的数据路径重新启动终端 A；执行客户端命令 `get client2`，应得到 `online`，而 `get course` 应仍为 `NOT_FOUND`。该流程已纳入 2026-08-31 Windows 发布版真实验收并通过。
